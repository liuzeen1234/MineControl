# 单箱仓库与 home 卸货（Minecraft 26.2）

鱼骨宏主背包9–35槽空位不超过2格，或者检测到受伤/血量低于10时，暂停挖矿，释放输入，依次执行 `/delhome kuang`、`/sethome kuang`、`/home home`。

回仓后等待加载和落地，只识别视线正前方、交互距离内的普通箱子或陷阱箱，不扫描附近替代箱子。打开后要求54格大箱子。本次卸货只在内存中锁定该箱子的坐标，关闭界面后仍只重新打开同一个箱子；箱子暂不可交互时等待，不更换箱子。

不再读取或生成 `fishbone-storage.json`，不长期保存箱子坐标或仓库home坐标。仓库home应事先设置为面对目标箱子的站位和视角。宏发送命令后等待100客户端tick，再以落地、界面可用及连续视线目标检查识别箱子；这不能独立证明服务器已接受传送命令。

满箱不停止：持续读取同一箱子，等待运输腾出空间后继续存入，无固定重试次数上限。快照过期、单次没有搬动物品等普通错误重读后重试。手动停止、死亡、断线或世界变化仍会中断。主背包已经卸空时，即使最后一批恰好填满箱子，也可进入恢复和返矿流程。

仅搬运主背包9–35槽，保留快捷栏、装备和副手，不删除、丢弃或替换物品。卸空后等待血量20、饱食度20，再执行 `/home kuang`；确认返回原矿点后继续挖矿。

`fishbone-unload-state.json` 仍保存临时返矿世界和位置，在回仓前写入，成功返矿后删除；中断时保留。重启恢复时重新回仓、识别前方箱子并卸空，再恢复和返矿，避免将未完成卸货误当作已完成。调度在该记录存在时排除传送位移，不重置路线。

回归：`./gradlew :java-sdk:homeStorageTest :java-sdk:fishboneMiningTest :java-sdk:miningSchedulerTest`。覆盖无仓库配置、不同朝向、受伤空背包恢复、STALE_CONTAINER、持续无进展、初始满箱和中途满箱在异步运输腾空后继续、最后恰好填满及只打开同一个箱子。

宏产物仍为独立可执行jar，不打包进主Mod，不自动预装。真实满箱运输场景只有在自然遇到并完成后才算实测通过，回归模拟不能替代客户端证据。
