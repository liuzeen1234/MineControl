# Issue #1：旧版游戏内宏功能验收

日期：2026-11-15。目标：[Issue #1](https://github.com/liuzeen1234/MineControl/issues/1)。

## 实现范围

1.20.1 / 1.20.4 共用旧版宏管理、添加文件、设置页面及客户端接入；列表构造 API 的差异由各版本 `MacroFileList` 桥接。

- F8 和标题/暂停菜单入口；手动添加源码或可执行 jar、刷新列表、选择启动/停止、删除到 `.trash`。
- Java 宏进程连接公共协调器，接入身份、权限、调度、退出世界与客户端关闭清理。
- HUD、默认 F9 全部停止、改绑及未绑定时 F9 备用停止。
- 执行宏/JSON 宏屏蔽物理键鼠、文字和滚轮，保留管理页面操作及 Mod 注入输入；释放系统光标并按焦点恢复。
- 设置页即时保存输入屏蔽开关。
- 宏程序仍为用户手动导入的独立 jar；主 Mod 仅携带隐藏公共运行库。

## 游戏内验证

分别启动当前源码的 Fabric 开发客户端，使用独立目录 `run-issue1-1.20.1`、`run-issue1-1.20.4` 和新建创造世界，均使用 Java 17、Fabric Loader 0.15.11。1.20.1 使用缓存资源跳过资源下载任务，未跳过客户端启动。

两版均完成：

- 标题宏入口、设置页开关往返、进入世界后 F8 管理界面。
- 独立测试探针实际启动 Java 源码宏，完成 31 项输入隔离、注入输入、F8、F9、改绑、轮询、输入清理和光标检查。探针通过游戏原生回调入口模拟物理事件，并单独检查 GLFW 光标模式；不等同于人工敲击每一种操作系统键盘设备。
- 将临时生成的 Java 17 可执行 `issue1-probe.jar` 通过“添加文件”路径输入手动导入，选择第二行并点击启动；日志先记录 `ISSUE1_JAR_STARTED`，移动两 tick，三秒后记录 `ISSUE1_JAR_COMPLETED` 和“已结束”。
- 正常保存并退出测试世界、关闭客户端。1.20.4 另启动持续源码宏后退出世界，确认进程停止；1.20.1 另通过删除按钮确认源码进入 `.trash`。

1.20.1 截图复核时发现列表默认背景遮盖顶部按钮，已关闭旧列表背景/边缘阴影，重启客户端复核最终布局。

完整输入检查列表：[1.20.1](1.20.1-input-capture.json)、[1.20.4](1.20.4-input-capture.json)。界面和 HUD 截图在同目录。

## 复现

```sh
./gradlew legacyTestJar -Pmc=1.20.1
# 将 build/test-mods/minecontrol-legacy-test-mc1.20.1.jar 放入独立开发实例 mods。
# 创建 config/input-capture-test.trigger 后进入测试世界。
./gradlew runClient -Pmc=1.20.1 -PrunDir=run-issue1-1.20.1
# 1.20.4 使用对应参数和探针。
```

结果写入实例的 `config/input-capture-test-report.json`。探针默认不加载，且不会进入正式 Mod。不同目标的 Gradle 任务可能清理上一目标输出，客户端加载时顺序运行各目标。

本次不扩展旧版附近玩家、伤害、聊天命令、容器、方块扫描或 Xaero 专用接口；依赖这些接口的宏仍需要 26.2。本轮不声称覆盖跨维度、多服务器和所有第三方 Mod 组合。

## 构建与打包检查

三个目标均通过构建和根项目协议检查，26.2 另通过方块类型检查；SDK 完整检查在 1.20.1 构建中通过，之后两个目标不重复 SDK 检查。CLI 的 5 项单元测试通过。

打包检查发现历史生成目录残留的 `entity-click-program.jar` 会被增量 jar 带入；资源处理现在先清理自己的生成目录，再复制当前资源。重建两版后确认主 Mod 仅嵌入 `minecontrol/macro-runtime.jar`，不包含测试探针或宏程序。见 [打包检查](package-check.json)；运行日志摘要：[1.20.1](1.20.1-runtime.log)、[1.20.4](1.20.4-runtime.log)。
